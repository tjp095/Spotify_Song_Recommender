Spotify playlist completion: Assignment 2, parts 2-4¶

Exploratory analysis · Modeling · Evaluation

This notebook completes parts 2, 3, and 4 of the attached assignment PDF. The lecture overview numbers the topics differently; the PDF's numbering is used here. The task is to recover withheld tracks from an existing playlist. The inputs are its observed tracks, the fitting playlists' interactions, and optional static audio metadata; the output is a ranked list of tracks absent from the seed playlist.

Comparison: a training-popularity baseline plus three distinct models: playlist-neighborhood collaborative filtering, PureSVD latent factors, and an audio-centroid content model. Model and feature selection use validation NDCG@20. The test set is used only after selection. All outputs below are executed results, not illustrative numbers.

Reading guide: Part 2 explains the data and preprocessing; Part 3 describes the models and implementation; Part 4 gives the evaluation protocol, comparisons, uncertainty, and limitations. Code is included so the HTML can be reviewed without executing it.

2. Exploratory analysis, data collection, and preprocessing¶

2.1 Data context and provenance¶

The supplied file, data/songs620.csv, is the dataset used throughout. Each row associates a Spotify track with a playlist ID (pid) and a playlist position (pos). It also includes artist/album identifiers, names, duration, and Spotify-style audio descriptors. The filename does not imply that the file contains only 620 songs.

Its playlist schema and IDs 0-999 are consistent with an enriched subset of Spotify's Million Playlist Dataset (MPD). That origin is an inference: the repository has no collection script, source URL, license record, sampling description, or enrichment date, so this notebook cannot authenticate the exact source or how the audio features were fetched. The observed data are therefore described as the supplied Spotify playlist CSV. No new Spotify API collection is performed, and URL columns are never fetched.

For context, Spotify describes the original MPD as a resource for automatic playlist continuation, containing one million playlists and over two million tracks [R1]. That description concerns the original dataset; this CSV is much smaller. The data contain no listener IDs, ratings, skip logs, playlist titles, or observation timestamps. A playlist is the recommendation context, not a verified individual listener. pos is an ordering field rather than a timestamp, so this study makes no temporal forecasting claim.

2.2 Clean interactions before splitting¶

An interaction is binary playlist membership: a track is either present or absent. Repeated occurrences of a track in one playlist are collapsed before splitting, so the same membership cannot appear in both a seed and its held-out targets. Distinct playlists sharing a track are retained: that overlap is the collaborative signal.

Track metadata are checked for inconsistencies across repeated occurrences, then one consistent record per track is used. The index column Unnamed: 0, redundant track IDs, URLs, names, album fields, and pos do not enter the predictive models. Names are used only for readable examples; artist IDs are used for the diversity diagnostic.

def load_data():
    raw = pd.read_csv(ROOT / "data/songs620.csv")
    assert raw[["pid", "track_uri"]].notna().all().all()
    edges = raw.drop_duplicates(["pid", "track_uri"]).copy()
    # Stable vocabulary from static catalogue metadata, without interaction counts.
    tracks = raw.drop_duplicates("track_uri").sort_values("track_uri").reset_index(drop=True)
    pids = np.sort(edges.pid.unique())
    track_index = {s: i for i, s in enumerate(tracks.track_uri)}
    pid_index = {p: i for i, p in enumerate(pids)}
    edges["u"] = edges.pid.map(pid_index)
    edges["i"] = edges.track_uri.map(track_index)
    return raw, edges, tracks, pids


def split_edges(edges, shape):
    rng = np.random.default_rng(SEED)
    rows = {s: [] for s in ["train", "validation", "test"]}
    for u, group in edges.groupby("u", sort=True):
        items = rng.permutation(np.sort(group.i.to_numpy()))
        assert len(items) >= 5
        # Floor each holdout at 20%; remainder belongs to train.
        h = max(1, int(len(items) * .2))
        for name, values in zip(rows, [items[2*h:], items[:h], items[h:2*h]]):
            rows[name].extend((u, int(i)) for i in values)
    matrices = {}
    for name, pairs in rows.items():
        u, i = np.array(pairs).T
        matrices[name] = csr_matrix((np.ones(len(u), dtype=np.float32), (u, i)), shape=shape)
    a, b, c = matrices.values()
    assert a.multiply(b).nnz == a.multiply(c).nnz == b.multiply(c).nnz == 0
    assert a.nnz + b.nnz + c.nnz == len(edges)
    assert all(np.all(x.getnnz(axis=1) > 0) for x in matrices.values())
    manifest = pd.concat([pd.DataFrame(pairs, columns=["u", "i"]).assign(split=name)
                          for name, pairs in rows.items()], ignore_index=True)
    manifest.to_csv(OUT / "split_manifest.csv", index=False)
    return matrices


def audio_features(tracks, observed, representation):
    cols = CORE if representation == "core" else NUMERIC
    x = tracks[cols].apply(pd.to_numeric, errors="coerce").replace([np.inf, -np.inf], np.nan)
    # Avoid letting an extreme duration dominate the geometry.
    if "duration_ms" in cols:
        x["duration_ms"] = np.log1p(x["duration_ms"].clip(lower=0))
    imputer = SimpleImputer(strategy="median", keep_empty_features=True)
    x_fit = imputer.fit_transform(x.loc[observed])
    scaler = StandardScaler().fit(x_fit)
    z = scaler.transform(imputer.transform(x)).astype(np.float32)
    if representation == "full":
        # Fixed semantic categories: no category order is assumed.
        cats = []
        for col, values in [("key", range(-1, 12)), ("mode", [-1, 0, 1]),
                            ("time_signature", range(-1, 8))]:
            v = pd.to_numeric(tracks[col], errors="coerce").fillna(-1).to_numpy()
            cats.extend((v == value).astype(np.float32)[:, None] for value in values)
        z = np.hstack([z] + cats)
    return normalize(z).astype(np.float32)

2.3 What the data show, and why it matters¶

There are 66,263 raw rows, reduced to 65,409 unique playlist-track memberships after removing 854 repeated memberships. The file contains 1,000 playlists, 36,203 tracks, and 9,963 artists. Only 0.181% of the playlist-track matrix is observed. Playlist lengths range from 5 to 246 unique tracks, with a median of 49.

The track distribution has a substantial long tail: 26,901 tracks (74.3%) appear in only one playlist, while the most frequent 1% of tracks account for 10.5% of unique memberships. Popularity is therefore a relevant baseline, but many test targets will lack collaborative evidence. This motivates comparing a content model with two collaborative models, and reporting warm-track and cold-track performance separately.

No supplied column has missing values, and the numerical model inputs are finite. Repeated metadata records agree for all modeled features and artist IDs. A defensive median imputer remains in the content pipeline; it is fitted only on tracks observed in fitting interactions. Duration is log-transformed and continuous features are standardized on those same fitting tracks. Held-out track metadata can be transformed because the catalogue is assumed known; their interaction labels are never used to fit preprocessing. Zero tempo or energy values are retained as supplied rather than silently interpreted as missing. Their upstream meaning cannot be checked from this CSV.

Energy and loudness correlate strongly at the unique-track level (Pearson r = 0.788). This suggests redundant descriptors and motivates testing a compact feature set against a fuller one. Correlation alone does not establish predictive usefulness.

2.4 Split and information boundary¶

Within each playlist, unique tracks are shuffled using seed 42. Two disjoint sets of floor(0.2 * playlist_length) tracks are assigned to validation and test; the remainder forms training. All playlists have at least five tracks, so every partition has at least one interaction per playlist. The resulting split has 40,013 training, 12,698 validation, and 12,698 test memberships.

During selection, models fit only the training matrix and recommend against validation targets. After all configurations are frozen, each model is refitted on training plus validation (52,711 memberships) and recommends against the untouched test targets. This uses the validation tracks as additional seeds at final evaluation, for every model. Validation and test scores consequently have different seed lengths and are not a train-test generalization-gap estimate.

This is a random missing-track completion experiment on known playlists and a known static catalogue. It does not measure new-playlist performance, future listening, track ordering, or chronological next-song prediction. Tracks may occur in several playlists; each individual membership is assigned exactly once. The complete mapping is saved in output/split_manifest.csv with separate item and playlist vocabularies.

3. Modeling¶

3.1 Inputs, outputs, and course connections¶

Let $B_{pi}=1$ when fitting playlist $p$ contains track $i$, and zero otherwise. For each playlist the model outputs a score $s(p,i)$ for every track in the catalogue. Observed seed tracks are removed before taking the highest scores. Unobserved memberships are unknown, rather than explicit dislikes.

The lecture recommendation.pdf [L1] introduces cosine similarity, neighborhood collaborative filtering, low-dimensional latent factors, implicit feedback, and ranking metrics. Those ideas motivate the first two learned approaches and the evaluation. regression.pdf [L2] motivates categorical encodings, feature transforms, control of model complexity, and a distinct validation set. The implementation uses those ideas for audio features and model selection. The latent-factor model below is a truncated SVD adaptation, not a claim to reproduce the lecture's rating-loss optimizer exactly.

3.2 Baseline and three models¶

Method Score or objective Role and tradeoff
Popularity baseline $s(p,i)=\sum_q B_{qi}$ Ranks tracks by fitting playlist count. Cheap and robust, but has no playlist-specific preferences and favors popular tracks.
Playlist-kNN collaborative filtering $c(p,q)=B_pB_q^T/(\|B_p\|\|B_q\|)$; $s(p,i)=\sum_{q\in N_k(p),q\ne p}c(p,q)^a B_{qi}$ Uses shared tracks to find related playlists. Interpretable, but sparse overlap and cold items are difficult. The diagonal similarity is set to zero.
PureSVD latent factors Approximate $\min_{\mathrm{rank}(\hat B)\le d}\|B-\hat B\|_F^2$ using randomized truncated SVD; $\hat B=(BV_d)V_d^T$ Low-rank representations share information across playlists. Rank limits complexity. The zero-filled reconstruction objective is only a surrogate for ranking and gives unknown entries a zero target.
Audio centroid content model Normalize item feature vectors $z_i$; $h_p=\mathrm{normalize}(\sum_{i:B_{pi}=1}z_i)$; $s(p,i)=h_p^Tz_i$ Fits scaling from known tracks and builds a playlist profile. It can score catalogue tracks without fitting interactions. A single centroid may blur mixed-genre playlists and cannot capture all cultural or semantic preferences.

PureSVD uses TruncatedSVD with seven power iterations and fixed randomness. The returned transformed matrix is $BV_d$, so multiplying by components_ produces the rank-$d$ reconstruction. There is no stochastic-gradient learning rate or early stopping to tune. Its chosen rank is selected only with validation NDCG@20.

The centroid is a content model fitted through preprocessing and profile construction; it does not learn a supervised neural network. The three models represent neighborhood, latent-factor, and content-based approaches, in addition to the baseline.

3.3 Feature representations and hyperparameter search¶

Collaborative features: a sparse binary playlist-track matrix. Frequencies are computed after deduplication, not from repeated positions. Neither collaborative model uses audio, names, artist IDs, or test interactions.

Core audio representation: danceability, energy, loudness, valence, and tempo. Full representation: those five plus speechiness, acousticness, instrumentalness, liveness, and log-duration, followed by fixed one-hot encodings of key, mode, and time signature. The encodings avoid imposing a numerical ordering on categories; they do not model harmonic distance. Reserved categories make the full vector 35-dimensional. Continuous columns are standardized; category indicator columns remain 0/1. Each resulting item vector is L2-normalized. These choices impose equal coordinate weights rather than learning the ideal importance of each descriptor.

The predefined grid contains 12 configurations: popularity (1), kNN with neighbors in {20, 50, 100} and similarity power in {1, 2} (6), SVD with rank in {16, 32, 64} (3), and core/full audio (2). Each model family selects its highest validation NDCG@20 configuration. A stable first-configuration rule breaks any exact ties. No grid is expanded after inspecting test scores.

class Ranker:
    """Small score interface; no test labels are accepted by this class."""
    def __init__(self, name, parameters=None):
        self.name, self.parameters = name, parameters or {}

    def fit(self, interactions, tracks):
        start = perf_counter()
        self.b = interactions.tocsr().astype(np.float32)
        self.pop = np.asarray(self.b.sum(axis=0)).ravel()
        self.n_items = self.b.shape[1]
        if self.name == "Playlist-kNN":
            b_norm = normalize(self.b)
            similarity = (b_norm @ b_norm.T).toarray()
            np.fill_diagonal(similarity, 0)  # Never use a playlist as its own neighbor.
            k = self.parameters["neighbors"]
            neighbors = np.argsort(-similarity, axis=1, kind="stable")[:, :k]
            u = np.repeat(np.arange(self.b.shape[0]), k)
            v = neighbors.ravel()
            weights = similarity[u, v] ** self.parameters["power"]
            self.w = csr_matrix((weights, (u, v)), shape=similarity.shape)
        elif self.name == "PureSVD":
            self.svd = TruncatedSVD(n_components=self.parameters["rank"], n_iter=7,
                                    random_state=SEED)
            self.embedding = self.svd.fit_transform(self.b)
        elif self.name == "Audio centroid":
            self.features = audio_features(tracks, self.pop > 0, self.parameters["features"])
            self.profiles = normalize(np.asarray(self.b @ self.features))
        elif self.name != "Popularity":
            raise ValueError(self.name)
        self.fit_seconds = perf_counter() - start
        return self

    def scores(self, first, last):
        if self.name == "Popularity":
            return np.broadcast_to(self.pop, (last-first, self.n_items)).copy()
        if self.name == "Playlist-kNN":
            return (self.w[first:last] @ self.b).toarray()
        if self.name == "PureSVD":
            return self.embedding[first:last] @ self.svd.components_
        return self.profiles[first:last] @ self.features.T


def top_items(scores, seen, popularity, k=50):
    """Exact top-k, with deterministic popularity then item-ID tie breaks."""
    scores = np.asarray(scores).copy()
    scores[seen] = -np.inf
    assert np.isfinite(scores[~seen]).all()
    cutoff = np.partition(scores, len(scores)-k)[len(scores)-k]
    above = np.flatnonzero(scores > cutoff)
    tied = np.flatnonzero(scores == cutoff)
    tied = tied[np.lexsort((tied, -popularity[tied]))][:k-len(above)]
    selected = np.r_[above, tied]
    return selected[np.lexsort((selected, -popularity[selected], -scores[selected]))]


def recommend(model, max_k=50):
    start = perf_counter()
    ranked = []
    for first in range(0, model.b.shape[0], 32):
        last = min(first+32, model.b.shape[0])
        scores = model.scores(first, last)
        for offset, u in enumerate(range(first, last)):
            seen = np.zeros(model.n_items, dtype=bool)
            seen[model.b[u].indices] = True
            top = top_items(scores[offset], seen, model.pop, max_k)
            assert len(np.unique(top)) == max_k and not seen[top].any()
            ranked.append(top)
    return np.array(ranked), perf_counter()-start

3.4 Architectural choices, efficiency, and overfitting¶

The binary matrix uses SciPy CSR storage, with one stored value per fitting membership. The kNN implementation builds the playlist-by-playlist similarity matrix, then retains only the selected neighbors. With 1,000 playlists this dense intermediate is approximately 4 MB in float32. It is practical here, but its quadratic playlist memory would be inappropriate at MPD scale; approximate neighbor retrieval or blocked similarity search would be needed there.

SVD stores approximately $d(P+I)$ factor entries, and content scoring stores $I F$ item-feature entries. Ranking scores are generated in batches of 32 playlists, avoiding a full playlist-by-catalogue score matrix. A batch of 32 by 36,203 float32 scores is about 4.6 MB. CSR interactions and batched multiplication keep this dataset small enough for CPU execution. Reported times cover fitting and top-50 scoring/ranking, not CSV parsing, EDA, metric calculation, or bootstrap uncertainty.

Top-k selection uses partitioning, with explicit tie handling: descending model score, then descending fitting popularity, then stable track ID. Thus every model uses the same deterministic fallback for tied or unsupported predictions. Content scores can be negative after centering; their ordering remains valid. Seed tracks are always masked, and a playlist is never its own kNN neighbor.

The rank constraint regularizes SVD; k and the similarity power control neighborhood locality. The audio model has no supervised coefficient fitting, but representation selection still risks validation overfitting. A fixed grid and a held-out test set limit that risk. Training reconstruction is not reported as recommendation quality, since rewarding recovery of already-seen tracks would be misleading.

Rating regression is not directly supported because no ratings exist. Ordinary accuracy on all playlist-track pairs would be dominated by missing entries. A sequence transformer would require a different ordered-task design and substantially more training context. These models could be studied later, but are not necessary to compare the course's similarity and latent-factor approaches here.

4. Evaluation¶

4.1 Metrics and candidate set¶

Every model ranks the entire 36,203-track catalogue, removing only tracks in that playlist's fitting seed. No sampled negative set or minimum-popularity filter is used. Validation targets are not removed during validation; test targets are not removed during test evaluation. Catalogue metadata are assumed available even for tracks with zero fitting interactions.

The primary metric is macro NDCG@20, which rewards retrieving relevant tracks near the top of a short recommendation list. For held-out set $T_p$, and relevance $r_{pj}=1$ if the track at rank $j$ is in $T_p$:

$$\mathrm{DCG@K}(p)=\sum_{j=1}^{K}\frac{r_{pj}}{\log_2(j+1)},\qquad \mathrm{NDCG@K}(p)=\frac{\mathrm{DCG@K}(p)} {\sum_{j=1}^{\min(K,|T_p|)}1/\log_2(j+1)}.$$

Recall@K is the number of retrieved targets divided by $|T_p|$; Precision@K divides by K; HitRate@K is one if at least one target is retrieved. Each metric is averaged equally over playlists, so long playlists do not dominate. We report K = 10, 20, and 50, with K = 20 fixed before selection.

Coverage@20 is the number of distinct tracks recommended across all playlists divided by the catalogue size. Artist diversity@20 is the mean number of distinct artists per list divided by 20. Novelty@20 is the mean $\log_2((P+1)/(n_i+1))$ of recommended tracks, using fitting playlist count $n_i$. Higher novelty therefore means lower fitting popularity; it is not evidence that a listener enjoys the recommendations.

NDCG and recall match the recovery task more directly than MSE, which would compare scores without calibrated rating labels, or classification accuracy, which treats nearly all unknown pairs as negatives. Ranking relevance is still incomplete: unobserved tracks could be enjoyable, so this is exact-membership recovery rather than a direct measure of satisfaction. The metrics are not numerically comparable to the official MPD challenge's differently configured evaluation [R2].

def evaluate(ranked, target, fit_matrix, tracks):
    rows = []
    pop = np.asarray(fit_matrix.sum(axis=0)).ravel()
    artists = tracks.artist_uri.fillna("unknown").to_numpy()
    discounts = 1 / np.log2(np.arange(2, 52))
    for u, recs in enumerate(ranked):
        truth = target[u].indices
        hits = np.isin(recs, truth)
        row = {"u": u, "target_count": len(truth), "seed_count": fit_matrix[u].nnz}
        for k in [10, 20, 50]:
            h = hits[:k].sum()
            row.update({f"Recall@{k}": h/len(truth), f"Precision@{k}": h/k,
                        f"NDCG@{k}": float(hits[:k] @ discounts[:k]) / discounts[:min(k,len(truth))].sum(),
                        f"HitRate@{k}": float(h > 0)})
        warm, cold = truth[pop[truth] > 0], truth[pop[truth] == 0]
        row["WarmRecall@20"] = np.isin(recs[:20], warm).sum()/len(warm) if len(warm) else np.nan
        row["ColdRecall@20"] = np.isin(recs[:20], cold).sum()/len(cold) if len(cold) else np.nan
        row["cold_targets"] = len(cold)
        row["Novelty@20"] = float(np.mean(np.log2((fit_matrix.shape[0]+1)/(pop[recs[:20]]+1))))
        row["ArtistDiversity@20"] = len(np.unique(artists[recs[:20]]))/20
        rows.append(row)
    return pd.DataFrame(rows)


def paired_uncertainty(a, b):
    """Percentile paired bootstrap + two-sided paired sign-flip test."""
    rng = np.random.default_rng(2026)
    d = np.asarray(a) - np.asarray(b)
    boot = d[rng.integers(0, len(d), size=(2000, len(d)))].mean(axis=1)
    extreme = 0
    for _ in range(20):
        perm = (rng.choice([-1, 1], size=(500, len(d))) * d).mean(axis=1)
        extreme += np.count_nonzero(np.abs(perm) >= abs(d.mean()) - 1e-15)
    lo, hi = np.quantile(boot, [.025, .975])
    return float(d.mean()), float(lo), float(hi), (extreme+1)/10001

4.3 Final refit, test evaluation, and uncertainty¶

Each frozen configuration is refitted on train plus validation. The next code is the first experiment stage that uses test labels. It saves per-playlist results and top-50 recommendations so the aggregate values can be audited.

For the primary metric, 2,000 paired bootstrap samples of playlists produce a 95% percentile interval for each model's difference from popularity. We also use a 10,000-draw two-sided paired sign-flip test with the +1 Monte Carlo correction. Holm adjustment covers the three model-versus-baseline tests. Mean-score intervals on the plot also resample playlists. These intervals are conditional on this split and fitted models; shared tracks and overlapping playlist tastes mean playlist independence is an approximation. They do not quantify uncertainty from recollecting the dataset, changing the split, or refitting on bootstrap datasets.

4.4 Main findings¶

Playlist-kNN is the validation-selected model and has the strongest observed test performance. It reaches NDCG@20 = 0.07098, Recall@20 = 0.07222, and HitRate@20 = 0.434. Popularity reaches 0.01081, 0.01244, and 0.100, respectively. The paired NDCG improvement is 0.06016, with a 95% interval of [0.05370, 0.06727] and Holm-adjusted p = 0.00030. Thus shared-track neighborhoods add a clear signal over overall fitting popularity on this split. The sign-flip p-value is limited by the finite number of randomization draws.

PureSVD also clearly improves over popularity, reaching NDCG@20 = 0.05891 and Recall@20 = 0.06124. Its paired NDCG difference is 0.04810 (95% interval [0.04239, 0.05392], Holm-adjusted p = 0.00030). The kNN score is higher than SVD's, although the formal tests shown here compare each model with popularity and do not test the kNN-SVD difference. Local overlaps may preserve playlist-specific associations that a 64-dimensional reconstruction smooths away; this is an interpretation, not an experimentally isolated cause.

The audio-centroid model does not beat popularity overall. Its test NDCG@20 is 0.00885 and Recall@20 is 0.01175. Its NDCG difference from popularity is -0.00196, with interval [-0.00562, 0.00219] and adjusted p = 0.32437. The interval includes zero. Audio coherence in EDA therefore does not translate into reliable exact-track recovery with this simple model. Artist identity, language, semantic theme, and multi-modal playlist structure may matter beyond a centroid of low-dimensional descriptors. Those explanations would need additional ablations.

Absolute recall remains modest: even kNN recovers about 7.2% of a playlist's held-out tracks in its top 20, on average. This is a difficult sparse-catalogue task, and a large improvement over a weak baseline is not equivalent to a production-ready system.

4.5 Cold tracks, coverage, and playlist length¶

5,623 of 12,698 test interactions (44.3%) concern tracks with zero interactions in the final fitting matrix. This is a cold-interaction condition within a known catalogue, not absence of metadata. Such tracks have no positive popularity or neighborhood evidence, and SVD has no observed column signal. All three collaborative/ popularity approaches have zero cold-target Recall@20 in this run. The audio model achieves 0.01155. Warm Recall@20 is 0.11779 for kNN, 0.09147 for SVD, 0.01701 for popularity, and 0.00522 for audio.

Warm and cold recalls are macro averages over the playlists with at least one target of that type; they need not combine to the overall recall using the global cold interaction fraction. Cold status is defined solely by the final fitting matrix.

The content model trades recovery for reach: it recommends 22.69% of catalogue tracks across its top-20 lists, compared with 10.24% for kNN, 6.31% for SVD, and 0.091% for popularity (33 distinct tracks). Audio also has higher artist diversity and lower-popularity recommendations. These metrics show a different behavior, not automatically better recommendations. A future hybrid could use content for cold candidates and collaborative scores for warm candidates, but no unrun hybrid result is claimed here.

For kNN, NDCG@20 is 0.0524, 0.0665, and 0.0869 for playlists with 1-20, 21-50, and 51+ fitting seeds. These groups contain 264, 336, and 400 playlists. More seeds provide more context, but group differences also reflect playlist content and target counts; they do not establish a causal benefit of adding seeds.

For this dataset and completion setting, use playlist-kNN with 50 neighbors and cosine weights as the primary method. It is simple, fast at this scale, and gives the best validation and observed test performance. Keep popularity as a fallback. PureSVD is a compact alternative; content deserves further study for tracks without interaction evidence, despite its weak aggregate recovery.

The main limitations are the unverified extraction/enrichment history, a small playlist sample, many singleton tracks, one random split, a known-playlist evaluation, and incomplete relevance labels. There are no listener IDs or timestamps with which to test personalization across people or chronological generalization. No listening study establishes user satisfaction, diversity preference, or fairness. A larger sample, repeated predefined splits, a new-playlist holdout, and a carefully validated hybrid would provide stronger evidence. Test results here are final reporting, not feedback for another round of tuning.

References and relationship to the supplied slides¶

[L1] Julian McAuley, course lecture, Recommender Systems (recommendation.pdf). Supplied Google Drive slides. Relevant topics: similarity-based recommenders, cosine similarity, latent factors, cold start, and precision/recall at K.

[L2] Julian McAuley, course lecture, Supervised learning - Regression (regression.pdf). Supplied Google Drive slides. Relevant topics: categorical features, feature transforms, overfitting, regularization, and train/validation/test separation.

[L3] Course lecture, Assignment 2 (assignment2_fa26.pdf). Supplied overview. Used for guidance on feature comparisons, baselines, scaling, and model selection. Section numbering in this notebook follows the separately attached assignment PDF.

[R1] Ching-Wei Chen (2020), The Million Playlist Dataset... Remastered. Spotify Research. Primary context for the original MPD and its playlist-continuation purpose; it does not authenticate the local CSV's derivation.

[R2] Hamed Zamani, Markus Schedl, Paul Lamere, and Ching-Wei Chen (2019), An Analysis of Approaches Taken in the ACM RecSys Challenge 2018 for Automatic Music Playlist Continuation. Paper. The challenge studies continuation from seed tracks and metadata. Its evaluation protocol differs from the present small-sample top-20 experiment, so its scores are not used as comparable baselines.

[R3] Irene Teinemaa, Niek Tax, and Carlos Bentes (2018), Automatic Playlist Continuation through a Composition of Collaborative Filters. Paper. The authors combine collaborative filters for different playlist aspects. This motivates testing interaction-based approaches; the present kNN/SVD comparison does not reproduce their ensemble or optimization procedure.

[R4] Andres Ferraro, Dmitry Bogdanov, Jisang Yoon, KwangSeob Kim, and Xavier Serra (2018; arXiv 2019), Automatic playlist continuation using a hybrid recommender system combining features from text and audio. Paper. Their system combines an audio/title-aware factorization model with a co-occurrence model using ranking fusion. The simple audio-only centroid here is a much more limited comparison; its negative aggregate result does not refute that hybrid approach.
